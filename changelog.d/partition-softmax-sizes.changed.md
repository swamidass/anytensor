Require ``total_length`` on ``partition_softmax`` / ``partition_ids`` (shape-size for the flattened axis; not a silent ``sum(partitions)``). ``num_segments`` is not an argument on partition helpers — it is ``shape(partitions)[0]``. Segment ops still require ``num_segments``. ``cache`` is a decorator (preferred on library apply; GraphNetwork uses it; **sticky** so stacked applies reuse ``n_node`` / ``n_edge``), a scoped reentrant context, and ``enable``/``disable`` for use outside a block; it is a dict of dicts with the partition→segid map at ``cache["partition"]`` (**one entry per partition vector**; the ids' leading size is the flattened total). ``partition_ids`` is the only partition helper that talks to that map; other partition functions call ``partition_ids`` so a cache hit is shared. If a cached expansion's length does not match ``total_length`` (host Python ints), that entry is purged, a warning is issued, and ids are recomputed; tracing skips the check. ``purge``/``purge_cache`` drops one tensor from one namespace. GC callbacks hold only a weakref to the namespace map so a long-lived tensor cannot zombie the block. ``anytensor.jraph.partition_softmax`` keeps official jraph's third positional ``sum_partitions`` (alias of ``total_length``) but now requires it.
